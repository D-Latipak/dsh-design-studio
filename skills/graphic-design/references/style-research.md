# 风格研究关（Style Research）——风格只能从用户的话和当场联网查到的设计里来

> 一句话：**不选风格，查风格。** 用户怎么描述，你就去互联网上找"他说的那种东西"，
> 把看到的真实设计读成参数，再把参数变成画面。任何内置目录、任何"经典做法"都不许替代这一步。

---

## 一、三条铁律

1. **起点只能是用户的原话**（`designs/<slug>/brief-lock.md` 的 R 编号）。
   不许先想"这是瑞士风/港风/Y2K"，再去套它的套路。风格名字是**结论**，不是输入。
2. **必须当场联网抓真实设计。** 不许凭记忆、不许凭训练里见过的海报、不许拿上一次的参考板当答案
   （可以复用文件，但这次必须重新核对它是否还对得上这次的话）。
3. **每条 DNA 都要有出处。** 要么来自用户某条原话，要么来自某张参考 `#NN`。说不出出处就删掉。

---

## 二、第一步：把用户的话拆成检索维度

把 `brief-lock.md` 里所有要求摊开，按这八个维度归类（缺的维度就空着）：

| 维度 | 用户可能怎么说 | 你补的检索词（中/英都要试） |
|---|---|---|
| 题材/内容 | 「关于旧书店」「深水埗街市」 | bookstore, second-hand books, street market |
| 年代 | 「八十年代」「民国」「未来」 | 1980s, Republican-era Shanghai, retro-futurism |
| 媒介/工艺 | 「像丝网印」「像报纸」「像胶片」 | risograph, screen print, newsprint, film grain |
| 版式 | 「密密的字」「大留白」「分三栏」 | dense typographic layout, editorial grid, three-column |
| 字体 | 「粗黑标题」「手写」「等宽」 | heavy grotesque headline, handwritten script, monospace |
| 色彩 | 「墨绿」「褪色」「高饱和」 | deep green, faded palette, saturated |
| 氛围/情绪 | 「潮湿暧昧」「冷」「热闹」 | humid, moody, neon reflections, cold, bustling |
| 参照物 | 「像王家卫」「像无印良品」 | Wong Kar-wai poster, MUJI packaging |

**规则：**

- 用户的原词尽量原样保留，再补 1–2 个同义词和英文译法；
  **不要**把「潮湿暧昧」直接换成「迷幻六十年代」这类流派名——那是把他的话换成你的词。
- 拿不准的词，先用 `web_search` 查这个词在设计语境里指什么，再决定检索词。
- 用户点名了具体作品/设计师/品牌：先核实它存在（`web_search`），再直接找它的图；
  同时要判断他说的是"学它的做法"还是"只要那个感觉"——不确定就问。

**检索式至少 2 组**，形如：

```
"<年代> <媒介> <题材> <版式特征>"
"<氛围词> <字体特征> <色彩> design"
"<用户点名的作品/设计师> poster"
```

例：用户说「像老式火车票那种细密排字、墨绿、不要照片」→

```
1) vintage train ticket typography dense small type
2) 老式 火车票 印刷 排字 复古
3) ephemera ticket layout monospace grid
```

## 三、第二步：当场抓真实设计（范围 = 全球互联网，不设白名单）

**第一步永远是 `reference_search`**（本 bundle 的 MCP 工具：Bing 图搜 + 内置四站 + 任意 `url` 直链，
下载/质检/去重/拼版一次完成）：两三组词、中英文各来一遍，并传 `workspace`。
只有在工具列表里看不到它时，才退回 `web_search` + `New-ReferenceBoard.ps1 -Url`。
网站本身不是门槛——**任何真实存在的设计/图像都可以当参考**。

**脚本原生的四站（方便，不是限制）：**

| 源 | 适合抓什么 | 用法 |
|---|---|---|
| **Are.na** | 当代平面、版式、字体、海报的公开收藏 | `-Query` 默认开 |
| **Design Reviewed** | 平面设计史档案（海报/封面/广告高清原图） | `-Query` 默认开 |
| **Fonts In Use** | 真实项目的字体使用档案（字体搭配、字号关系） | `-Sources` 打开 |
| **It's Nice That** | 当代编辑设计、插画、品牌 | `-Sources` 打开 |

**任何其他网站（用 `-Url`）：** Behance、Dribbble、Pinterest、Instagram、X/Twitter、Reddit、Tumblr、
ArtStation、站酷、花瓣、小红书、Behance 专题、品牌官网与 VI 手册 PDF、出版社/杂志官网、
博物馆与图书馆的数字馆藏、旧书/票据/包装的拍卖行照片、电影截图、街拍、展览现场、
YouTube/B 站视频封面、甚至建筑与织物的照片——只要能读到画面结构，就值得收。

- 页面：`-Url "<页面>"` 会自动抽 `og:image` / `twitter:image`；
- 直链图：`-Url "<https://.../x.jpg>"` 直接下载（带图片扩展名的 URL 会走直链分支）；
- 抓不到 og:image、或站点反爬：换一个镜像/转载页，或 `web_fetch` 读出图片直链再喂 `-Url`。

**参考不需要版权。** 它是研究材料：不需要许可、不需要署名、**不能放进成品**。
只有要进成品的图，才转去素材关走许可流程（`free-assets.md`）。这条界线别搞混。

**兜底（默认关闭）：** AIC / Met / Cleveland / Commons / Openverse 馆藏。
馆藏关键词检索很松（搜 `swiss style poster` 会返回瑞士卫队盔甲），只在确实需要历史图像时开，
并且必须逐张核对年代/媒介/类别。

**命令：**

```powershell
# 内置源按检索词抓
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<技能>\scripts\New-ReferenceBoard.ps1" `
  -Query "vintage train ticket typography","ephemera ticket layout" -Slug <slug>-ref -Workspace "<工作区>"

# 任意网页 / 任意图片直链
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<技能>\scripts\New-ReferenceBoard.ps1" `
  -Url "https://www.behance.net/gallery/123456/x","https://example.com/poster.jpg" -Slug <slug>-ref

# 需要字体使用证据时
  ... -Sources arena,designreviewed,fontsinuse -Query "<检索词>"
```

**硬下限（不达标不许过审）：**

- ≥ 4 张留在板上；
- ≥ 2 个来源，或 ≥ 2 组检索词；
- 宽 ≥ 1200px 最好；很多平台原图只有 700–1000px，脚本会自动把它们收为「低清备选」，
  主列表不足 4 张时补位（并给出警告）。低清图看得清结构就行，别拿它量精确字号。

**不再要求"≥3 张来自专业设计源"。** 来源只影响你对它的信任程度，不影响它能不能当参考。
要排除的只有"不是设计的东西"：教程截图、模板商店页、搜索引擎结果页缩略图、
AI 生成图（那是别人模型的输出，学不到可靠结构）、带假字的水印样机。

**不够怎么办：** 换词（同义词、英文、更具体的年代/媒介）、换平台（Pinterest/Reddit/档案馆/品牌站）、
换语言（日/韩/德/俄/西），用 `web_search` 找页面再 `-Url`。
**不许**用"感觉差不多"的图凑数，**不许**因为抓不到就凭记忆画。

## 四、第三步：逐张读图，写精读卡

`read_image` 先看 `board.png` 建立整体印象，再逐张看 `img/NN`。**只看缩略图就写 = 没做。**

`designs/<slug>/reference-study.md`：

```markdown
## #01 <标题> — <来源> — <作者/年代>
- 语法定位：<这是什么类别的设计：海报/封面/票据/包装…>
- 网格与比例：<几栏、栏宽比、边距占宽比、画幅比>
- 层级与字号跨度：<最大字/最小字大致比例、几层>
- 色彩：<主色/辅色/强调色，各自大致占比>
- 字体：<衬线/无衬线/等宽/书写体；字重；字距>
- 图文关系：<图与字谁压谁、有没有留白位、图文比例>
- 母题与工艺：<贯穿全稿的结构/材质/印刷特征>
- 节奏：<疏密变化在哪、视线怎么走>
- 可迁移规则 3 条：<能拿到这稿里的具体规则>
- 不学不抄 3 件：<只属于那件作品、不能带走的东西>
- 对应需求：R01 / R03（它回答了用户的哪条要求）
```

**交叉分析**（3 共性 + 3 差异 + 1 打架取舍）：三条共性 → 可能是这种风格的结构规则；
三条差异 → 说明哪些是可变的；打架的那一条 → 说明你更信哪张，为什么（要能回到用户的话）。

**估不出的数字写「看不清」，不许编。**

## 五、第四步：合成风格 DNA（可执行参数）

`designs/<slug>/style-dna.md`。这不是一篇散文，是**施工参数**：

```markdown
# 风格 DNA · <slug>
| 参数 | 取值 | 出处 |
|---|---|---|
| 画幅/比例 | 4:5 竖版 | R02「发朋友圈」 |
| 网格 | 3 栏不等宽，栏距 8pt | #02 #04 |
| 字号跨度 | 标题:正文 = 6:1，最小字 7pt | #01 + R01「细密排字」 |
| 字体族 | 标题：粗黑无衬线；正文：等宽 | R04「像机器打印的」 |
| 色彩 | 底 #14342B 60% / 纸色 #EFE6D3 30% / 朱红 10% | R03 + #03 |
| 图文关系 | 全字，无照片；文字压在满版底色上 | R05「不要照片」 |
| 母题 | 贯穿全稿的一条 1pt 票根虚线 | #02 |
| 节奏 | 上部密、下部空，信息集中在票根框内 | #01 #04 |
| 允许的不对称 | 标题左边缘人为超出栏线 3pt | #02（偏离一处，用户可推翻） |
```

**判定规则：**

1. 每条后面必须有 `R0N` 或 `#NN`；两者都没有的，删掉。
2. **与用户原话冲突的参考特征，删参考，不删用户。**
   例：参考里是满版照片，但用户说「不要照片」→ DNA 里图文关系写"全字无照片"，并在备注里记下参考的哪部分没有被采用。
3. 用户的要求之间打架 → 停下来问，不自己取舍。
4. DNA 写完后自检一句：**"如果换一个人来做，只看这份 DNA，能不能做出同一个风格？"** 不能就说明还太虚。

## 六、第五步：交付过审（没有 `refs-approved.md` 不许动手）

一条消息里给齐：

1. **编号整板图**（`board.png`，图上带 #NN）；
2. **逐张清单**（#NN 标题 / 来源 / 为什么留着）；
3. **精读结论 3–6 行**（这组参考的共同结构是什么）；
4. **DNA 摘要 3–6 行**（最关键的几个参数）；
5. **三问**：是不是这个感觉 / 哪张最准 / 哪里跑偏了；
6. **默认通过范围**（"如果你不回，我就按 #01#03#04 这组和上面的 DNA 做"）。

用户原话**逐字**写进 `designs/<slug>/refs-approved.md`（包括"不对""太脏了"这类否定，也要逐字）。
摆出后**结束这一回合**，设静默时钟（见章程 1.5 第 6 条）。

**过审之后**：DNA 冻结成这一版的施工依据。用户中途改口 → 更新 `refs-approved.md`（追加，不覆盖），
按新话重做对应部分，不要拿旧 DNA 硬撑。

**用户说不要过审 / 不要参考 / 直接出**：照做。把原话记进 `refs-approved.md`
（「用户要求跳过参考关：<原话>」），然后按他的要求直接做。这一步是流程，不是特权——
**用户的要求永远高于流程**。

## 七、常见坑

| 坑 | 表现 | 处理 |
|---|---|---|
| 把用户的话翻译成流派名 | "潮湿暧昧"→"迷幻六十年代"，然后按迷幻做 | 回到原词，按原词造检索式 |
| 用记忆代替检索 | 直接开始画"我知道这种风格长什么样" | 停，先抓板 |
| 抓的是"好看的设计"而不是"他说的设计" | 板子很漂亮，但和 R01 无关 | 逐张问"它回答了哪条需求"，回答不了的删 |
| 只读缩略图 | DNA 全是空话（"现代""简约"） | 逐张看 `img/NN`，写具体数字 |
| 参考侵入了成品 | `file.place` 了参考图 | 立刻撤，参考只进判断 |
| 抓不到就降级 | "网络不好，我先按经典做法做" | 重试 3 轮 → 摆给用户决定，不许静默降级 |
| 把 DNA 写成审美宣言 | "要克制、要有呼吸感" | 换成可执行参数：留白占比、字号比、色值 |
