# 方向确认（Directions Gate）——只在用户没给方向时才会用

> 一句话：**用户给了方向就照做，不给方向才摆候选；候选必须全部来自用户的话和已过审的参考，不许来自任何内置风格目录。**
> 文件位置：`designs/<slug>/direction-approved.md`。

---

## 一、先判断：这次到底要不要摆三个方向

| 情况 | 做法 |
|---|---|
| 用户明确说了风格/做法（「就要像老票据」「不要照片」「标题全竖排」） | **不摆方向**，直接按 `brief-lock.md` + `style-dna.md` 做。歧义处最多问一句 |
| 用户给了参考图/参考站/明确作品 | **不摆方向**，按参考做（仍要走风格研究关把参数读出来） |
| 用户只给了内容，没给任何形式倾向 | 可以摆 2–3 个方向给他挑，避免猜错 |
| 用户说「随你发挥」「你定」 | 可以摆方向，也可以直接做；直接做的话在决策单里写清你为什么这么定 |

**硬规则：**

- 摆设候选**不能**被用来削弱用户已经说过的要求。三个候选都必须逐条满足 `brief-lock.md`。
- 用户说「继续」只是同意往下走，**不等于**同意你改方向。
- 任何候选都不许以「这是经典做法」「这样更安全」「最近流行」为理由。

---

## 二、要摆方向时的做法

### Phase 1 · 唯一一轮提问（最多 3 个）

只问**你不知道、且会改变结果**的事：受众 / 核心信息 / 使用场景 / 尺寸，
以及「有没有'就要那种感觉'的图或网站」。**不要**问「你想要什么风格」——风格研究关会去查。
用户不回就按最佳判断补假设并标出来，不枯等。

### Phase 2 · 三个方向从哪来

**全部**来自这三处，且优先级从高到低：

1. **用户原话里的不同侧重**。同一句话可以有三种落地方式，比如「密」可以是密排正文、
   密排装饰、或密到没有留白的满版。每种都必须在 DNA 里说得清对应哪条要求。
2. **已过审参考里的不同路径**。参考板里如果存在两种明显不同的结构（不是换配色），可以各做一个。
3. **内容本身的结构**。内容有流程 → 三步式；内容有对比 → 分栏对置；内容有地图 → 空间式。
   form 要来自内容，不是来自你的偏好。

**禁止**：按"当前秒数"抽风格、按流派清单抽条目、按"最近没做过"抽颜色、按"著名设计师"直接套手法。
**没有风格目录可抽。**

### Phase 3 · 三张缩略图（不是三份 moodboard）

- 每张是这个方向最关键的一屏：真字体、真配色、真骨架、真标题，约 480×300；
- `New-ContactSheet.ps1` 拼成一页，自己先看一遍；
- 建立 `designs/<slug>/directions.md`，每个方向写四行：**借的是什么具体规则 / 主角素材 / 骨架 / 它对应哪条要求**。

### Phase 4 · 展示，然后停

摆出：三张缩略图 + 六宫格（如有）+ 每个方向四行说明 + 一句「另外几张是备选」。
**摆出来就结束这一回合**，设静默时钟（默认 10 分钟）。
到点没回：按**你自评最符合用户要求**的那个方向继续，写 `silent-approve` + 理由，并告知用户。
用户选了：把他原话逐字写进 `direction-approved.md`，之后才排版。

### Phase 5 · 落档

`direction-approved.md` 至少包含：

```markdown
- 项目 / 日期 / 展示了哪几张 / 备选哪几张
- 用户选择（原话，逐字，不改写）
- 选定方向：dir-N，一句话
- 混合选择（如有）：布局来自 dir-X、颜色来自 dir-Y
- 明确否定 / 偏好（原话，逐字）
- 静默时钟：mode / deadline / taskId / 默认选择与理由
- 豁免（用户明说不用摆方向时，记原话）
```

## 三、三个方向不要"看起来像一个人做的"（只在这种时候适用）

如果确实摆了方向，三个候选挤成同一套骨架就失去了意义。开版前自查：

1. **去色测试**：转灰度后骨架还分得清吗？分不清 = 只有配色差异。
2. **骨架测试**：把三张的线框并排，阅读路径、分栏、焦点位置至少有两个方向不同。
3. **要求测试**：每个方向都能说出它满足了 `brief-lock.md` 的哪几条；说得出才算候选。

注意：这一节是**给"没方向的用户"提供真实选择**的手段，不是"为了不一样而不一样"的规则。
用户已经定了一个方向时，**不要**用这三条去改他的东西。

---

## 四、和风格研究关的关系

- 风格研究关（`style-research.md`）**永远先做**：先查清"他说的那种东西"长什么样。
- 方向确认只是在这之后决定"这一版具体走哪条解释"。
- 没有 `refs-approved.md`（用户明确说不要参考的除外）不许摆方向；
  没有 `direction-approved.md`（摆过方向的情况下）不许进排版。
- 外观账本 `designs/_ledger.json` 只是历史记录：**可以**拿来看"我最近是不是老用同一招"（自查），
  但**不能**作为"必须避开某配色/字体"的限制——用户要什么就做什么。
